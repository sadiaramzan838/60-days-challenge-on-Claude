Architecture overview

Planner and Executor run once, upstream of the loop, to set strategy and produce a first draft. From round 1 onward, Evaluator → Critic → Improver form the closed loop: the Evaluator scores the current draft against a personalization-weighted rubric, the Critic finds concrete gaps, the Memory Manager folds what worked (and didn't) into running notes, the Safety Monitor checks honesty and tone, and — unless a stop condition just fired — the Improver rewrites the draft using all of that context before the loop hands it back to the Evaluator. The stop check runs every round, in a fixed priority order: plateau first, then threshold, then the hard cap as a safety fallback only. Whichever fires first ends the loop and routes the best draft to the Final Reviewer for QA and polish.

Extension ideas

  • Add a Researcher agent that pulls real facts about the target brand before Planning.
  • Run 2–3 Executor drafts in parallel and let the Evaluator pick a winner before the loop starts.
  • Persist memory notes across multiple target clients so later pitches reuse what worked.
  • Swap the rubric weights per platform (email vs. DM vs. Upwork proposal).
  • Let the Safety Monitor hard-stop the loop if it flags a false claim, not just log a warning.
Further prompts for building more advanced autonomous systems
"Add a Researcher agent that web-searches the target brand and feeds real findings into the Planner's brief."
"Give the Safety Monitor veto power: if it flags a false or exaggerated claim, force an extra Improver pass before the loop can stop on threshold."
"Turn this into a multi-target batch runner: same freelancer profile, five different target clients, run the loop for each and compare final scores."
"Add a human-in-the-loop checkpoint: pause after the first plateau and let the user manually edit the draft before resuming the loop."
